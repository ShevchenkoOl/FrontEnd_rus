# Лекция 11: Асинхронность (Event Loop, Promises, Async/Await, Fetch)

Весь код выполняется процессором компьютера. Код, который мы до сих пор писали, был **синхронным**, то есть занимал процессор на все время своего исполнения. К примеру, скорость выполнения цикла по массиву зависит исключительно от скорости процессора.

Но существуют операции, взаимодействующие с внешним миром. К примеру, обмен данными с сервером в сети происходит намного медленнее, чем получение данных из оперативной памяти. Если такие операции обрабатывать синхронно, процессор будет просто «висеть» и простаивать во время сетевого запроса вместо того, чтобы выполнять другой код. Пользователь при этом увидит зависший интерфейс.

---

## 1. Синхронный vs Асинхронный код

### 🧱 Синхронный код
Выполняется строго последовательно. Каждая инструкция ожидает, пока выполнится предыдущая. 
> **Аналогия:** Представьте очередь в кассу на вокзале. Вы не можете начать покупать билет, пока его не приобретет человек перед вами. Точно так же люди, стоящие за вами, ждут вас.

**Характеристики:**
* Выполнение идёт шаг за шагом.
* Блокирует выполнение следующих операций.
* Прост в понимании и отладке.
* **Где используется:** Арифметика, условия, циклы, простая логика в памяти.

```javascript
console.log("First log");
console.log("Second log");
console.log("Third log");
// Результат: 1, 2, 3 (строго по порядку)
```

### 🔀 Асинхронный код
В асинхронной модели сетевой запрос на сервер не остановит приложение — программа просто «поручит» эту задачу браузеру и продолжит выполнять другие операции (например, реагировать на клики пользователя). Когда запрос завершится, программа получит уведомление и результат.

**Характеристики:**
* Не блокирует выполнение программы.
* Позволяет выполнять несколько задач «параллельно» (логически).
* Сложнее для понимания.
* **Где используется:** Запросы к серверу (API), таймеры, задержки, загрузка файлов.

```javascript
console.log("First log");

setTimeout(() => {
  // Выполнится позже, не блокируя код ниже
  console.log("Second log");
}, 2000);

console.log("Third log");
// Результат: First log, Third log, Second log
```

## 2. Под капотом: Event Loop (Цикл событий)

Как однопоточный JavaScript умудряется делать несколько вещей одновременно? 

1. Сначала JS выполняет весь синхронный код, помещая его в **Call Stack** (Стек вызовов).
2. Когда встречается асинхронная операция (например, `setTimeout` или запрос), она передается в **Web APIs** (возможности самого браузера или Node.js). JS идет дальше, не дожидаясь ответа.
3. После завершения фоновой работы Web API передает колбэк-функцию (результат) в **Очередь задач (Task Queue)**.
4. **Event Loop** постоянно проверяет: *«Пуст ли сейчас Call Stack?»*. Как только стек вызовов полностью освобождается, Event Loop берет задачу из очереди и кидает её в стек для выполнения.

> **Асинхронность ≠ Многопоточность:**
> * **Синхронный подход:** Вы (повар) готовите кофе, ждете, пока он сварится, потом делаете тосты, ждете их, подаете всё клиенту.
> * **Асинхронный однопоточный подход:** Вы ставите кофе на плиту, заводите таймер. Ставите тосты в тостер, заводите таймер. Пока всё готовится, вы протираете столы. Зазвенел таймер тостера — вы достали хлеб.
> * **Многопоточный подход:** Вы нанимаете двух помощников. Один делает только кофе, второй — только тосты. (В JS это реализуется через Web Workers).

## 3. Macrotasks и Microtasks

Асинхронные задачи делятся на две очереди с разным приоритетом.

**Macrotasks (Макрозадачи):**
`setTimeout`, события пользователя (клики, скролл).
👉 *«Сделай это позже, когда будет время»*. Между выполнением макрозадач браузер может обновить экран или обработать новый клик.

**Microtasks (Микрозадачи):**
`Promises` (Промисы), `queueMicrotask`.
👉 *«Как только освободишься — сделай это ПЕРВЫМ»*. Микрозадачи имеют наивысший приоритет. Если появилась микрозадача, Event Loop выполнит её до любой макрозадачи.

Рассмотрим классическую задачу с собеседований:
```javascript
console.log("start");                  // 1. Синхронно

setTimeout(() => {
  console.log("timeout");              // 4. Macrotask
}, 0);

Promise.resolve().then(() => {
  console.log("promise");              // 3. Microtask (Приоритет!)
});

console.log("end");                    // 2. Синхронно
```
**Результат:** `start` → `end` → `promise` → `timeout`.

## 4. Promises (Обещания)

`Promise` — это объект, представляющий результат (успешный или нет) асинхронной операции, который будет получен в будущем.

У Promise есть 3 состояния:
1. **pending** — ожидание. Операция началась, результата ещё нет.
2. **fulfilled** — успешно выполнено (результат получен).
3. **rejected** — отклонено (произошла ошибка).

**Зачем нужен Promise?**
Он спасает от «ада колбэков» (глубокой вложенности функций), дает понятный порядок действий и единый способ обработки ошибок.

### Синтаксис и обработка:
```javascript
// 1. Создание
const promise = new Promise((resolve, reject) => {
  const isSuccess = true;
  
  if (isSuccess) {
    resolve("Всё отлично, вот данные!"); // Успех
  } else {
    reject("Упс, произошла ошибка");     // Провал
  }
});

// 2. Использование (Потребление)
promise
  .then(result => {
    // Срабатывает, если был вызван resolve()
    console.log(result);
  })
  .catch(error => {
    // Срабатывает, если был вызван reject()
    console.error(error);
  })
  .finally(() => {
    // Срабатывает ВСЕГДА в самом конце (например, чтобы скрыть лоадер)
    console.log("Промис завершил работу");
  });
```
☯️ **Итого:** `.then` — для результата, `.catch` — для ошибки, `.finally` — для завершения.

## 5. Практика: Искусственный запрос и Спиннер

Часто на фронтенде нам нужно сымитировать работу сервера (пока бэкенд еще не готов). Мы оборачиваем `setTimeout` в `Promise`.

```javascript
const user = { id: 1, name: "Alex" };

function showSpinner() { console.log("⏳ Спиннер крутится..."); }
function hideSpinner() { console.log("⏹️ Спиннер остановлен"); }

// Функция-заглушка (Имитация API)
function getUser() {
  showSpinner();
  
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const isSuccess = true;
      isSuccess ? resolve(user) : reject("Ошибка сети");
    }, 1500);
  });
}

// Вызов
getUser()
  .then(data => console.log("Получены данные:", data))
  .catch(error => console.error("Ошибка:", error))
  .finally(() => hideSpinner()); // Передаем ссылку на функцию
```

## 6. Работа с сервером (HTTP, API, Fetch)

* **HTTP/HTTPS** — протоколы передачи данных. Это «ПДД» интернета. HTTPS — это тот же HTTP, но защищенный (данные шифруются).
* **API** — набор правил общения программ. Интерфейс описывает, что можно попросить сделать сервер и что он вернет в ответ.
* **REST API** — архитектурный стиль взаимодействия. Мы отправляем HTTP-запрос (например, GET или POST), а сервер присылает нам данные в формате **JSON**.

### Функция `fetch()`
Встроенная функция браузера для HTTP-запросов. `fetch(url)` всегда возвращает Promise!

```javascript
const URL = "https://jsonplaceholder.typicode.com/users/1";

// Рекомендуемый паттерн: Внешняя обработка данных
function fetchUser() {
  return fetch(URL)
    .then(response => {
      if (!response.ok) {
        throw new Error(`Ошибка сервера: ${response.status}`);
      }
      return response.json(); // Распаковываем JSON (это тоже Promise!)
    });
}

// Использование по клику
const btn = document.querySelector('#load');

btn.addEventListener("click", () => {
  showSpinner();
  
  fetchUser()
    .then(user => console.log("User:", user))
    .catch(error => console.error(error.message))
    .finally(hideSpinner);
});
```

## 7. Современный синтаксис: `async / await`

Цепочки `.then().catch()` — это хорошо, но современный JavaScript предлагает более элегантный способ — `async/await`. Он позволяет писать асинхронный код так, как будто он синхронный.

* `async` ставится перед функцией. Означает, что функция всегда возвращает Promise.
* `await` ставится перед асинхронной операцией. Означает «поставь выполнение функции на паузу, пока Promise не выполнится». Ошибки при этом ловятся через стандартный блок `try...catch`.

```javascript
async function loadUsers() {
  try {
    // 1. Показать спиннер
    showSpinner();
    
    // 2. Ждем ответа от сервера
    const response = await fetch(URL);
    if (!response.ok) throw new Error("Ошибка");
    
    // 3. Ждем распаковки JSON
    const data = await response.json();
    
    // 4. Отрисовка
    renderData(data);
    
  } catch (error) {
    // Обработка ошибки
    console.error("Что-то пошло не так:", error);
  } finally {
    // Скрыть спиннер
    hideSpinner();
  }
}
```
