# Лекция 10: Веб-хранилище (Web Storage API) и JSON

Каждый раз, когда вы меняете цветовую тему между светлой и темной, просматриваете видео до определенной секунды или закрываете всплывающий баннер, популярные веб-приложения запоминают ваш выбор и при следующем посещении восстанавливают его.

По умолчанию состояние интерфейса сохраняется только в оперативной памяти текущей вкладки браузера и безвозвратно теряется после её закрытия. Чтобы избежать этого, информацию нужно где-то сохранить. На помощь приходит хранение данных прямо на компьютере пользователя.

**Web Storage API** — это встроенный в браузер интерфейс, который позволяет веб-приложениям сохранять данные на компьютере пользователя в виде пар «ключ–значение».

Данные, сохранённые с помощью Web Storage, доступны только внутри текущего браузера и для конкретного сайта (домена). Они не отправляются на сервер автоматически и используются исключительно на стороне пользователя.

---

## 1. Два типа веб-хранилища

Web Storage API предоставляет два типа хранилища. С точки зрения написания кода разницы между ними нет, разница лишь во времени жизни данных.

* **Локальное хранилище (`localStorage`) — постоянное:**
    Уникальное для каждого сайта и одинаковое на всех открытых вкладках этого сайта. Данные **не удаляются** даже после закрытия браузера или перезагрузки компьютера. Чтобы их удалить, пользователь должен вручную очистить кэш браузера, либо мы должны удалить их через JavaScript.
* **Хранилище сеансов (`sessionStorage`) — временное:**
    Время жизни данных ограничено сессией текущей вкладки. Как только пользователь закрывает вкладку — данные мгновенно и безвозвратно очищаются. На практике используется гораздо реже.

> ⚠️ **ИНТЕРЕСНО И ВАЖНО:**
> В веб-хранилище **категорически нельзя** хранить пароли, токены доступа, номера банковских карт и подобную конфиденциальную информацию. Если на сайт попадет вредоносный скрипт (XSS уязвимость), он без проблем прочитает эти данные.

## 2. Основные методы Web Storage

Для работы с хранилищем используются 4 основных метода и одно свойство. Синтаксис для `localStorage` и `sessionStorage` абсолютно идентичен.

**🔹 `setItem(key, value)`**
Создаёт новую запись в хранилище или обновляет значение, если запись с таким ключом уже существует.
```javascript
localStorage.setItem("theme", "dark");
```

**🔹 `getItem(key)`**
Возвращает значение из хранилища по указанному ключу. Если записи нет — возвращает `null`.
```javascript
const currentTheme = localStorage.getItem("theme"); // "dark"
```

**🔹 `removeItem(key)`**
Удаляет из хранилища конкретную запись с указанным ключом.
```javascript
localStorage.removeItem("theme");
```

**🔹 `clear()`**
Полностью и безвозвратно очищает **все** записи в хранилище текущего сайта.
```javascript
localStorage.clear();
```
*(В реальных проектах `clear()` используется редко: обычно при выходе пользователя из личного кабинета (Log out). В остальных случаях предпочтительно точечно удалять ключи через `removeItem`, чтобы не стереть чужие полезные настройки).*

**🔹 `length`**
Свойство, возвращающее количество записей в хранилище.
```javascript
console.log(localStorage.length);
```

## 3. Формат JSON (JavaScript Object Notation)

⚠️ **Главное правило Web Storage: он умеет хранить только СТРОКИ.**

Если мы попытаемся сохранить массив или объект напрямую (`localStorage.setItem("user", {name: "Alex"})`), браузер принудительно превратит его в бесполезную строку `"[object Object]"`.

Для сохранения объектов и массивов используется формат **JSON**.
JSON — это текстовый формат (строка), структура которого очень похожа на JS-объекты, но со строгими правилами:
* Все ключи обязательно берутся в двойные кавычки (`"key"`).
* Значения могут быть: числами, строками, булевыми значениями, массивами, объектами, `null`.
* В JSON **нельзя** хранить функции, методы, `Symbol` или `undefined`.

**Два главных метода для работы с JSON:**

1. **`JSON.stringify(data)`** — превращает объект/массив в строку (для отправки на сервер или сохранения в localStorage).
2. **`JSON.parse(string)`** — превращает строку обратно в полноценный объект/массив JS.

```javascript
const user = { name: "Alex", age: 26 };

// Превращаем в JSON-строку для хранения
const str = JSON.stringify(user); 
// Результат: '{"name":"Alex","age":26}'
localStorage.setItem("user", str);

// Достаем из хранилища и превращаем обратно в JS-объект
const parsedStr = localStorage.getItem("user");
const parsedUser = JSON.parse(parsedStr); 

console.log(parsedUser.name); // "Alex"
```

*(Примечание: В современных проектах файлы с расширением `.json` часто используются для хранения статических данных, например, списка городов или настроек. Внутри JS после `JSON.parse()` такой массив легко перебирать методами `.map()`, `.filter()`, `.forEach()`).*

## 4. Схема работы с localStorage на каждый день

**1️⃣ Простые значения (строка / число / булево)**
JSON не обязателен. Сохраняем как есть, при получении приводим к нужному типу.
```javascript
localStorage.setItem("username", "Alex"); // → "Alex"
localStorage.setItem("age", 26);          // → "26" (строка!)
localStorage.setItem("isAdmin", true);    // → "true" (строка!)

// Получение:
const age = Number(localStorage.getItem("age"));
```

**2️⃣ Сложные значения (объекты / массивы)**
JSON строго обязателен!
```javascript
const notes = ["note1", "note2"];

localStorage.setItem("notes", JSON.stringify(notes));
// В браузере хранится как сырая строка: '["note1","note2"]'

const savedNotes = JSON.parse(localStorage.getItem("notes")); 
// Снова получаем полноценный массив!
```

## 6. Самостоятельная практика: Mini Notes App (Список заметок)

**Требования:**
* При добавлении заметка появляется в списке.
* Все заметки сохраняются в `localStorage` как массив объектов.
* При перезагрузке страницы заметки восстанавливаются.
* Каждую заметку можно удалить.

**HTML:**
```html
<input type="text" id="noteInput" placeholder="Введите заметку">
<button id="addNote">Добавить</button>
<ul id="notesList"></ul>
```
