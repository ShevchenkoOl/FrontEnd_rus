# Лекция 9: События (Events) и обработка действий пользователя

События — это механизм, позволяющий JavaScript реагировать на действия пользователя (клики, ввод текста, движение мыши) или изменения состояния браузера (загрузка страницы, изменение размера окна).

Существует большое количество типов событий:
* события мыши и клавиатуры: `click`, `mousedowm`, `mouseup`, `dbclick`, `contextmenu`;
* события клавиатуры: `keydown`, `keyup`, `keypress`;
* события элементов формы: `input`, `change`, `submit`, `focus`, `blur`;
* события загрузки элементов: `load`, `DOMContentLoaded`;
* события окна браузера: `scroll`, `resize`;
* изменения состояния CSS-анимации: `animationstart`, `animationend`, `transitionend`.<br>
Полный список и подробную информацию можна посмотреть здесь👉[Event elements](https://developer.mozilla.org/en-US/docs/Web/API/Element/click_event) 
  
**Одно действие → несколько событий**
Одно и то же действие пользователя может вызвать цепочку событий. Например, при клике мышью происходят события: `mousedown`, `mouseup`, `click`. Их порядок строго фиксирован, и браузер вызывает обработчики именно в такой последовательности.

### Три главных термина событийной модели:
1. **Событие (event):** сигнал от браузера о том, что произошло какое-то действие (клик мыши, ввод текста, отправка формы).
2. **Обработчик (handler / listener):** функция, которую нужно выполнить при наступлении события (смена цвета кнопки при клике).
3. **Объект события (Event Object):** специальный объект, автоматически передаваемый в обработчик. Хранит информацию о событии (`event.target`, `event.type`, `event.key`).

## 1. Назначение обработчиков событий

В JavaScript существует три способа назначить обработчик элементу:

**1️⃣ Атрибут HTML (Inline Handlers) — Устаревший способ**
Смешивает HTML и JS, сложно поддерживать, невозможно переиспользовать.
```html
<button onclick="alert('Привет!')">Нажми</button>
```

**2️⃣ DOM-свойства (One-Property Handlers)**
Новый обработчик перезаписывает старый. Можно назначить только один.
```javascript
const button = document.querySelector('button');
button.onclick = function() {
    console.log('Клик сработал!');
};
```

**3️⃣ addEventListener() — Рекомендуемый способ**
Самый современный, гибкий и мощный метод. Позволяет назначать несколько обработчиков на одно событие, контролировать фазы и удалять их.

Конечно! Markdown любит чистоту и логическую структуру. Твой текст содержит очень важные технические детали (особенно про `signal`), поэтому его стоит оформить так, чтобы акценты считывались мгновенно.

Вот исправленный и профессионально оформленный вариант:

---

### **Синтаксис:**
```javascript
element.addEventListener(type, listener, [options]);
```
* **`type`**: Тип события (например, `"click"`, `"input"`).
* **`listener`**: Функция-обработчик, которая вызывается при наступлении события.
* **`options`**: Необязательный объект настроек, который дает тонкий контроль над поведением браузера.

**Или пример с именованной функцией (улучшает читабельность):**
```javascript
const button = document.querySelector(".my-button");

const handleClick = () => {
    console.log("Button was clicked");
};

button.addEventListener("click", handleClick);
```
На одном элементе может быть несколько обработчиков. Они будут вызываться в порядке их регистрации в коде.

---

### 📢 Дополнительно:
**Основные опции (options):**

1. **`capture`** (логическое значение)
    * **`false`** (по умолчанию) — обработчик сработает на **фазе всплытия** (*bubbling*).
    * **`true`** — обработчик сработает на **фазе погружения** (*capturing*).
    * *Используется редко, но критически важен для понимания того, как событие "путешествует" по DOM-дереву.<br>
    
**Фазы события и Настройки** `[options]`. Браузер обрабатывает события в 3 фазы:<br>
 - **Фаза погружения (Capture)** — событие идёт сверху вниз (от `document` до кнопки).<br>
 - **Фаза цели (Target)** — событие дошло до элемента, по которому кликнули.<br>
 - **Фаза всплытия (Bubbling)** — событие поднимается обратно вверх. По умолчанию все обработчики срабатывают именно здесь.<br>
На практике 90% случаев → хватает всплытия (по умолчанию)<br>
                            Фазы нужны, когда:<br>
                                - сложный UI (модалки, дропдауны, вложенные клики)<br>
                                - есть конфликт обработчиков<br>
                                - нужна глобальная логика (например, analytics)<br>
                                - ты делаешь библиотеку или framework-подобную логику<br>

2. **`once`** (логическое значение)
    * Если **`true`**, обработчик будет автоматически удален после первого же вызова. 
    * *Удобно использовать для кнопок отправки или инициализации, чтобы не прописывать `removeEventListener` вручную.*

3. **`passive`** (логическое значение)
    * Если **`true`**, вы говорите браузеру: «Я гарантирую, что НЕ буду вызывать `event.preventDefault()`».
    * **Зачем:** Это позволяет браузеру не ждать выполнения вашего скрипта и начать прокрутку (скролл) немедленно. 
    * ⚠️ **Важно:** Если при этой опции вы все же вызовете `preventDefault()`, в консоли появится ошибка.

4. **`signal`** (современный подход 🔥)
    * Позволяет передать `AbortSignal` от контроллера `AbortController`. Это дает возможность удалить обработчик (или сразу пачку обработчиков) одной командой.

```javascript
const controller = new AbortController();

button.addEventListener('click', handler, {
  signal: controller.signal
});

// Позже, в любой части кода:
controller.abort(); // Это мгновенно удалит обработчик
```
> **Это современная и мощная альтернатива `removeEventListener`.**

## 2. Метод removeEventListener()

Удаляет слушатель с элемента. Аргументы абсолютно аналогичны `addEventListener()`.

**Важно:** Для удаления нужно передать ссылку *именно на ту колбэк-функцию*, которая была назначена изначально.

**Когда нужен removeEventListener:**
* обработчик должен выполниться только один раз
* нужно вручную включать/выключать функции
* события слишком частые (`scroll`, `mousemove`) и могут тормозить интерфейс
* элемент удаляется из DOM (во избежание утечки памяти)

```javascript
const multiBtn = document.querySelector("#btn");

const firstCallback = () => console.log("First callback!");
const secondCallback = () => console.log("Second callback!");

const removeSecondCallback = () => {
  console.log("СРАБОТАЛ КЛИК — второй колбэк будет удалён");
  multiBtn.removeEventListener("click", secondCallback);
  multiBtn.removeEventListener("click", removeSecondCallback); // Удаляет сам себя
};

multiBtn.addEventListener("click", firstCallback);
multiBtn.addEventListener("click", secondCallback);
multiBtn.addEventListener("click", removeSecondCallback);
```

## 3. События формы

**Событие `input` (срабатывает при вводе)**
Срабатывает каждый раз, как только мы делаем изменения в поле ввода.
```javascript
input.addEventListener("input", (e) => {
  console.log(e.target.value);
}); 
```

**Событие `change` (срабатывает при потере фокуса)**
Срабатывает, когда мы закончили ввод и кликнули мимо инпута или выбрали пункт в `select`.
```javascript
select.addEventListener("change", (e) => {
  console.log(e.target.value);
});
```
>📢 **Примечание: `input.value` против `e.target.value`**
>На начальном этапе можно читать текст напрямую из переменной (например: `input.value`). Это работает. Но **«золотым стандартом»** и более безопасным подходом считается получение данных именно через объект события: `e.target.value`. Это позволяет писать универсальные функции и легко использовать делегирование событий.
 
**Событие `submit` (отправка формы)**
Отправка формы по умолчанию перезагружает страницу. Чаще всего это поведение нужно отменить с помощью `event.preventDefault()`.

Срабатывает в двух случаях: нажатие Enter внутри инпута или клик по кнопке `type="submit"`.

```javascript
form.addEventListener("submit", (e) => {
  e.preventDefault(); // Отменяем перезагрузку
  console.log("Форма отправлена, страница осталась на месте!");
});
```

### Чтение и запись значений input
Мы можем читать и записывать свойства элемента формы:
* `value` — текущее содержимое поля.
* `placeholder` — серый текст-подсказка.
* `checked` — состояние для чекбоксов (`true` / `false`).
* `files` — массив файлов для `<input type="file">`.

## 4. Объект события (Event Object)

**4.1** Для полноценной обработки нам недостаточно знать сам факт клика. Каждое событие передает в функцию специальный объект с деталями.

**Разница между `target` и `currentTarget`:**
* `event.target` — элемент, по которому был совершен реальный клик (самый глубокий тег).
* `event.currentTarget` — элемент, на котором висит обработчик `addEventListener`.

**4.2 Из полезных функций event:**
```javascript
document.addEventListener("keydown", event => {
  console.log("key", event.key);  // "a" (зависит от языка раскладки)
  console.log("code", event.code); // "KeyA" (НЕ зависит от раскладки, физическая кнопка)
});
```

## 5. События загрузки страницы (Создаем Спиннер)

JavaScript позволяет отслеживать, когда загрузилась структура страницы или страница целиком.

* **`DOMContentLoaded`** — срабатывает, когда браузер построил DOM-дерево. Картинки и стили могут быть еще не загружены.
* **`window.onload` (или событие `load`)** — срабатывает, когда загрузилось абсолютно всё, включая тяжелые изображения.

Это идеально подходит для создания красивого экрана загрузки (спиннера):

**HTML:**
```html
<div id="spinner" class="loader">⏳ Загрузка сайта...</div>
<div id="main-content" class="hidden">
  <h1>Добро пожаловать!</h1>
  <img src="heavy-image.jpg" alt="Фото">
</div>
```

**JavaScript:**
```javascript
const spinner = document.getElementById('spinner');
const content = document.getElementById('main-content');

// Ждем полной загрузки всех файлов и картинок
window.addEventListener('load', () => {
    // Прячем спиннер
    spinner.classList.add('hidden');
    // Показываем контент
    content.classList.remove('hidden');
});
```
