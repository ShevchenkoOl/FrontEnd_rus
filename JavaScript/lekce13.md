# Лекция 13: Сборщики проектов (Vite), ES-модули и архитектура приложения

## 1. Что такое сборщик проектов?
Представь, что ты строишь дом. Ты можешь носить кирпичи руками, мешать бетон в ведре палкой и сам вырезать стекла. Это сработает для крошечного сарая (простого сайта из одного файла), но для большого дома тебе нужна бетономешалка, подъемный кран и логистика.

**Сборщик проектов (Bundler или build tool)** — это и есть тот самый «подъемный кран» и «завод» для твоего кода. Это инструмент, который берёт твой исходный код (JS, CSS, картинки), обрабатывает его и превращает в готовый оптимизированный проект для запуска в браузере или выгрузки на сервер.



### 1.2 Зачем нужен сборщик?
Если кратко: сборщик берет сотни твоих маленьких файлов с кодом, стилями и картинками и превращает их в один-два компактных файла, которые браузер скачает и поймет максимально быстро.

### 1.3 Как мы жили без сборщика:
* **Много запросов:** Приходилось подключать каждый файл отдельно в HTML (`<script src="header.js"></script>`, `<script src="slider.js"></script>`...). Каждый такой тег — это отдельный долгий запрос к серверу.
* **Глобальная область видимости:** Переменные из разных файлов конфликтовали друг с другом.
* **Нет ES-модулей:** Нельзя было удобно использовать современный синтаксис `import / export`.
* **Нет автообновления (HMR):** Приходилось вручную нажимать F5 в браузере после каждого сохранения кода.
* **Нет оптимизации:** Код отправлялся пользователю огромным, с кучей пробелов и комментариев.

**Вывод:** Сборщик нужен, чтобы писать код удобно, а запускать — быстро!

### 1.4 Какие бывают сборщики:
* **Webpack** — старый, но мощный индустриальный стандарт. Очень гибкий, но сложный в настройке. Используется в больших Enterprise-проектах.
* **Parcel** — сборщик «без настроек». Простой старт, но меньше контроля. Хорош для небольших проектов.
* **Vite** (от фр. *быстрый*) — современный, молниеносный инструмент с минимальной настройкой. Использует современные возможности браузеров. Идеален для обучения и реальных проектов.

## 2. Как настроить и запустить Vite?

⚠️ *Vite — это не библиотека, которую подключают в HTML. Это инструмент, который запускается через терминал.*

Перед началом обязательно проверь, установлены ли у тебя Node.js и npm:
```bash
node -v
npm -v
```

### 2.1 Создание проекта:
В терминале пишем команду (приписка `@latest` говорит системе взять самую свежую версию):
```bash
npm create vite@latest
```
Дальше Vite начнёт диалог в терминале:
1. **Project name:** Вводим название (например, `todo-app`).
2. **Select a framework:** Выбираем **Vanilla** (чистый JS без фреймворков).
3. **Select a variant:** Выбираем **JavaScript**.
4. **Use rolldown-vite (Experimental)?** Выбираем **No**.
5. **Install with npm and start now?** Выбираем **Yes**. Vite сам скачает нужные библиотеки (`npm install`) и запустит локальный сервер для разработки.

### 2.2 Архитектура нашего проекта:

* `package.json` — главный файл конфигурации. В нем записаны:
  * Название и версия проекта.
  * `scripts`: команды для запуска. Все они запускаются через `npm run <имя>`.
    * `"dev": "vite"` — запуск проекта в режиме разработки (с автообновлением).
    * `"build": "vite build"` — оптимизация и сжатие готового проекта.
    * `"preview": "vite preview"` — локальная проверка финальной сборки перед выгрузкой в интернет.
  * `dependencies` и `devDependencies`: список библиотек, от которых зависит проект.
* `package-lock.json` — подробный технический отчет. Фиксирует точные версии всех библиотек, чтобы проект не сломался через год из-за чужого обновления. *Руками не трогаем!*
* **Папка `public`** — место для статичных файлов (иконки, шрифты), которые Vite не должен изменять.
* **Папка `src` (Source)** — «кухня», где происходит магия. Здесь лежат твои `.js` и `.css` файлы. При любом изменении файла в этой папке Vite мгновенно обновляет страницу в браузере.
* `index.html` — лежит в корне проекта. Это точка входа, из которой Vite тянет всю цепочку твоих файлов.

> ‼️ **Важно про Хостинг:** Если закинуть проект на Vite в обычный GitHub Pages, он не заработает (будет пустой экран). GitHub не умеет сам запускать сборку. Поэтому для современных проектов мы используем хостинги вроде **Netlify** или **Vercel** — они сами видят `package.json` и собирают проект (команда `build`), создавая финальную папку `dist`.

## 3. ES-модули (Import и Export)



Чтобы разбивать код на независимые файлы и переиспользовать его, мы применяем ES-модули.
Для их работы скрипт в HTML должен быть подключен с атрибутом `type="module"`:
```html
<script type="module" src="/src/main.js"></script>
```

Существует два вида экспорта:
1. **Named export (Именованный экспорт)** — самый строгий и популярный.
   ```javascript
   export const todos = [];
   export function addTodo() { ... }
   
   // При импорте нужны фигурные скобки и точные имена!
   import { todos, addTodo } from "./logic.js"; 
   ```
2. **Default export (Экспорт по умолчанию)** — используется, если файл отдает только одну главную сущность.
   ```javascript
   const todos = [];
   export default todos;
   
   // При импорте скобки не нужны, имя можно придумать любое
   import myTodos from "./logic.js";
   ```

### 📝 Самостоятельная работа: Калькулятор скидок (Vite + ES Modules)
**Цель:** Самостоятельно развернуть проект на Vite, закрепить навыки работы с ES-модулями (`import` / `export`) и научиться архитектурно отделять математическую логику от отрисовки интерфейса.

**Вводная:** Вам нужно написать мини-приложение, которое рассчитывает итоговую стоимость товара с учетом персональной скидки покупателя и обязательного налога (НДС). Главное правило: математика должна лежать строго в одном файле, а отображение чека на экране — в другом.

**🏆 Ожидаемый результат:** 
В браузере отображается корректный текстовый чек. В консоли разработчика нет ошибок. Математика работает в отдельном модуле, а `main.js` занимается только сборкой данных и выводом на экран.
