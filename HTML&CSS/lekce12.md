# Лекция 12: CSS-препроцессоры (SASS/SCSS)

**CSS-препроцессор** — это надстройка над CSS, которая расширяет его синтаксис. Она делает написание кода быстрее, а поддержку и рефакторинг — проще. Препроцессоры позволяют использовать переменные, вложенность, циклы и функции, которых не хватает в обычном CSS.

Самые популярные препроцессоры: **SASS**, **LESS** и **Stylus**. Мы будем изучать самый востребованный из них — **SASS** (и его современный синтаксис **SCSS**).

---

## 1. Основы работы и компиляция

Браузеры не понимают формат `.scss`, поэтому его нужно **компилировать** в обычный `.css`.

### Как настроить Live Sass Compiler в VS Code:

1. Установите расширение **Live Sass Compiler**.
2. Создайте файл `style.scss` в папке проекта.
3. Нажмите кнопку **«Watch Sass»** на нижней панели VS Code.
4. Файл `style.css` будет генерироваться автоматически при каждом сохранении.
5. Подключите итоговый файл в HTML:
```html
<link rel="stylesheet" href="css/style.css">

```

## 2. Архитектура проекта

Для удобства код делят на части («паршалы»). Файлы, начинающиеся с подчеркивания (например, `_base.scss`), не компилируются в отдельные CSS-файлы, а служат для импорта.

**Рекомендуемая структура:**

```text
project/
├── .vscode/             ← Настройки компилятора
├── css/
│   ├── style.css        ← Итоговый файл (развернутый)
│   └── style.min.css    ← Итоговый файл (сжатый для хостинга)
├── scss/
│   ├── style.scss       ← Точка входа (импортирует всё остальное)
│   ├── _base.scss       ← Базовые стили (reset, шрифты)
│   ├── _variables.scss  ← Переменные (цвета, размеры)
│   └── _components.scss ← Стили блоков
└── index.html

```

## 3. Настройка VS Code (settings.json)

Чтобы компилятор раскладывал файлы «по полочкам», создайте папку `.vscode` и файл `settings.json` внутри нее:

```json
{
  "liveSassCompile.settings.formats": [
    {
      "format": "expanded",
      "extensionName": ".css",
      "savePath": "/css"
    },
    {
      "format": "compressed",
      "extensionName": ".min.css",
      "savePath": "/css"
    }
  ],
  "liveSassCompile.settings.generateMap": false
}

```

> **Важно:** Не забудьте добавить папку `.vscode` в ваш `.gitignore`, чтобы служебные настройки не попадали на GitHub.

## 4. Основные возможности SCSS

### 4.1 Переменные (`$`)

Позволяют хранить значения (цвета, шрифты) в одном месте.

```scss
$primary-color: #060606;
$accent-color: tomato;

body {
  color: $primary-color;
}

```

### 4.2 Вложенность и амперсанд (`&`)

Вместо того чтобы дублировать родительские классы, мы вкладываем правила друг в друга. Символ `&` подставляет имя родителя (идеально для БЭМ).

```scss
.section {
  width: 100%;
  
  &__title {
    color: red;
  }
  
  &:hover {
    background-color: #eee;
  }
}

```

### 4.3 Шаблоны (`%`) и `@extend`

Используются для наследования общих кусков кода. В итоговом CSS они группируются через запятую.

```scss
%button-base {
  display: inline-flex;
  padding: 10px 20px;
  border-radius: 4px;
}

.button-success {
  @extend %button-base;
  background-color: green;
}

```

### 4.4 Миксины (`@mixin` и `@include`)

Похожи на функции. Позволяют передавать аргументы.

```scss
@mixin border-radius($radius) {
  border-radius: $radius;
}

.box {
  @include border-radius(10px);
}

```

### 4.5 Циклы (`@each`)

Автоматизируют создание однотипных классов (например, иконок).

```scss
@each $animal in dog, cat, bird {
  .#{$animal}-icon {
    background-image: url('../img/#{$animal}.png');
  }
}

```

## 5. Карты (Словари)

Карты позволяют хранить связанные данные в формате `ключ: значение`.

```scss
$colors: (
  'primary': #8e3329,
  'accent': #d98328,
  'background': #e9e9e9
);

// Функция-помощник для удобного доступа
@function getColor($key) {
  @return map-get($colors, $key);
}

body {
  background-color: getColor('background');
}

```

## 6. Сравнение SASS vs Нативный CSS (2024+)
Современный CSS активно развивается, заимствуя лучшие идеи у препроцессоров. Однако между ними всё ещё есть существенные различия.

### 1️⃣ Импорт модулей

* **В SASS:** Используем `@use "variables";`. Это происходит на этапе компиляции, поэтому браузер получает один готовый файл.
* **В обычном CSS:** Часто используют `@import url("button.css");`, но это считается медленным способом, так как загрузка файлов происходит последовательно.
* **Современный подход:** Подключать файлы напрямую через HTML: `<link rel="stylesheet" href="button.css">`.

### 2️⃣ Переменные

* **В SASS:** Объявляются через `$primary: blue;`. Используются при компиляции.
* **В CSS (Custom Properties):** Объявляются в `:root { --primary: blue; }` и вызываются через `var(--primary)`.
```css
      :root {
        --main-color: #3498db;
      }
      
      body {
        color: var(--main-color);
      }
```

* **💡 Важно:** CSS-переменные мощнее в **runtime** (режиме реального времени), так как их значения можно менять через JavaScript или медиа-запросы без перекомпиляции кода.

### 3️⃣ Шаблоны (%placeholder) и @extend

* **В SASS:** Позволяют наследовать стили без дублирования кода в HTML.
* **В обычном CSS:** Прямого аналога нет. Альтернатива — просто присваивать одному HTML-элементу два или более классов (например, `class="btn btn--success"`).

### 4️⃣ Вложенность (Nesting)

* **Раньше:** В CSS приходилось писать полные пути: `.card { ... } .card .title { ... }`.
* **SASS:** Всегда поддерживал удобную вложенность.
* **🔥 Революция:** С 2024 года нативный CSS поддерживает вложенность почти так же, как SASS!
  
```css
.card {
  padding: 20px;
  & .title { font-size: 20px; }
}

```

### 5️⃣ Уникальные фишки SASS

В обычном CSS до сих пор **нет аналогов** для следующих инструментов:

* **Карты (Maps):** Словари для хранения сложных наборов данных.
* **Миксины:** Возможность создавать переиспользуемые блоки кода с аргументами.
* **Циклы (@each):** Автоматическая генерация сотен классов за один раз.
